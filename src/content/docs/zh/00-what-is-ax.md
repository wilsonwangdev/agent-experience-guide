# 什么是智能体体验（AX）？

## 演进：UX → DX → AX

每当一种新型用户出现，就会有相应的设计学科诞生。

20 世纪 80 年代到 21 世纪初，**用户体验（UX）** 教会我们为人类设计图形界面。GUI、鼠标点击、视觉层级、响应式布局——所有这些都是为有眼睛和双手的人优化的。

21 世纪的前二十年，**开发者体验（DX）** 教会我们为开发者设计工具。API、文档、CLI、SDK、错误消息、开发者门户——所有这些都是为编写代码和集成系统的人优化的。

现在，在 2020 年代，**智能体体验（AX）** 是一门为 AI 智能体（Agent）进行设计的学科——这些智能体是能够浏览网站、调用 API、阅读文档并代替人类完成任务的软件。

```
UX:  人 ↔ GUI             （视觉交互）
DX:  开发者 ↔ API/CLI      （编程交互）
AX:  智能体 ↔ 服务/工具    （自主交互）
```

## 智能体是用户

最重要的一次思维转变：**智能体是一种用户角色（user persona）**，而不是一种取巧手段或边缘场景。

当你为无障碍访问设计时，你会考虑屏幕阅读器、键盘导航和对比度。你不会构建"单独的无障碍版本"——你会把同一个网站做得更好。

当你为智能体设计时，原则是一样的。你不会为你的服务构建单独的"智能体版本"。你构建同一个服务，让人和智能体都能使用它。这些改进通常会让所有人受益：结构化数据帮助搜索引擎，类型化错误（Typed Error）帮助调试，清晰的 API 边界帮助集成者。

## 为什么智能体体验在当下至关重要

三个汇聚的趋势使 AX 变得紧迫：

### 1. 智能体是增长最快的用户群体

ChatGPT、Claude、Gemini、Copilot 以及数百个专业智能体已经在浏览网页、调用 API 和完成任务。无论你是否为其设计过，来自主流平台的智能体都会访问你的网站。

### 2. 对智能体不友好的服务会被绕过

当智能体找不到你的产品、无法理解它、无法认证或无法使用时，它只会选择一个行得通的竞品。没有忠诚度，没有第二次机会。ora.ai 的数据显示，73% 的被扫描产品在智能体就绪（Agent-Ready）程度上仍然被评为 D 或 F 级。中位评分仅为 35/100。

### 3. "能读"与"能行动"之间的鸿沟正在扩大

智能体已经可以爬取和阅读网络上大部分内容。ChatGPT-User 能访问 81% 的网站，ClaudeBot 能访问 82%。但当智能体尝试*做点什么*——认证、调用 API、完成工作流——这些数字就会急剧下降。OAuth 元数据覆盖率仅为 1%，符合规范的带 PKCE 的 MCP 仅为 1%。**智能体能读，但不能行动。**

## 如何理解智能体体验

AX 不是关于构建聊天机器人，也不是关于为你的产品添加 AI 功能，而是要让你的服务能力对自主智能体变得可发现、可理解和可使用——就像你通过 API 让开发者能使用它们，或通过 GUI 让用户能使用它们一样。

关键维度：

| 维度 | UX | DX | AX |
|-----------|----|----|-----|
| **主要用户** | 人类（视觉） | 开发者（代码） | 智能体（自主） |
| **界面** | GUI、按钮、表单 | API 文档、SDK、CLI | llms.txt、MCP、结构化响应 |
| **上手引导** | 注册、教程 | 文档、快速入门、沙箱 | 自助认证、能力发现 |
| **错误处理** | Toast 提示、工具提示 | 错误码、堆栈跟踪 | 类型化错误、重试指导、机器可读状态 |
| **导航** | 菜单、链接、面包屑 | API 参考、站点地图 | 站点地图、llms.txt、能力索引（Capability Index） |
| **反馈** | 视觉状态变化 | 响应码、日志 | 结构化结果、进度事件 |
| **信任** | 品牌、评论、社交证明 | 正常运行时间 SLA、版本管理 | 机器可读来源、作用域权限 |

## 智能体就绪的六个阶段

一个智能体尝试使用你的产品时，会经历包含六个阶段的旅程。每个阶段都可能是一个死胡同——或是一个脱颖而出的机会。

### 阶段 1：可发现性（Discovery）（智能体能找到你吗？）
当智能体需要某个产品或服务来完成任务时，它会进行搜索。如果智能体找不到你——或从未听说过你——它们会选择别人。

### 阶段 2：身份标识（Identity）（智能体理解你是做什么的吗？）
到达后，智能体会构建一个心智模型：你的产品是什么、面向谁、在什么场景下使用。薄弱的结构会导致定位偏差和错误推荐。

### 阶段 3：认证与访问（Auth & Access）（智能体能认证并行动吗？）
只有当智能体能够认证、请求作用域并调用可用的端点时，意图才能成为行动。断裂的认证路径会制造死胡同。

### 阶段 4：集成（Integration）（你做好"管道"了吗？）
现在，智能体会尝试重复调用、工具调用、流式输出和错误恢复。脆弱的响应或缺失的平台原语会导致静默的任务失败。

### 阶段 5：错误与恢复（Errors & Recovery）（智能体能自我修复吗？）
当出现问题时，智能体需要类型化错误、重试指导和结构化响应——而不是"出了点问题"。良好的错误处理能将死胡同变为可恢复的路径。

### 阶段 6：终端用户体验（End-User Experience）（人类能通过智能体进行交互吗？）
当需要支付、确认或视觉决策时，智能体必须将控制权交给人。如果交接流程（Handoff Flow）薄弱，整个回路就会崩溃。

## AX 成熟度模型（Maturity Model）

```
Level 0 — 不可见（Invisible）        智能体完全无法找到或解析你的网站。
Level 1 — 可发现（Discoverable）     智能体能找到你并理解你是做什么的。
Level 2 — 可访问（Accessible）       智能体能认证并执行基本 API 调用。
Level 3 — 已集成（Integrated）       智能体能使用你的工具、流式响应、从错误中恢复。
Level 4 — 智能体就绪（Agent-Ready）  智能体能通过人类交接完成完整工作流。
Level 5 — 智能体原生（Agent-Native） 智能体和人类共享相同的操作模型、状态和权限。
```

可以把它类比为 Web 无障碍标准——它有不同的级别，每个级别都能为用户（在这里是智能体）解锁更多能力。
